    Alignment API¶

    Everything you need to bring two spatial modalities into one coordinate system, importable from smint.alignment. The functions are grouped by the task they serve, in the order you normally use them:

    Task Use it when Start with
    Pre-registration The datasets differ in scale, rotation or mirroring build_pretransform
    Centroid registration and refinement Both modalities come from the same section (post-staining) register_centroid_files
    ST–SM registration The modalities come from sequential sections register_sm_to_st
    Coordinate columns You want to know which columns SMINT will read detect_coordinate_columns

    To run a registration out of process, locally or on SLURM, see the Jobs API. For the files these functions read and write, see Data formats.

    from smint.alignment import register_centroid_files

table, result = register_centroid_files(
    "nuclei_centroids.csv", "xenium_cells.csv",
    source_cols=("x_centroid", "y_centroid"),
    output_path="nuclei_registered.csv",
)
print(result["tre_initial"][0], "->", result["tre_validation"][0])
print(table["registration_status"].value_counts())

    Coordinate conventions

    Everything here is plain (x, y), except inside the STalign wrappers: STalign works in row–column (y, x) order, and load_landmarks swaps the pair on load. transform_points returns (x, y) in the frame you choose with orientation.

    Pre-registration¶

    A coarse scale, rotation and flip, held as one 3×3 affine so it can be inspected, saved with save_transform and replayed. Run it before landmark picking or LDDMM when the two datasets start in different frames. Operations are applied flip → rotate → scale about the source centroid, then the source centroid is moved onto the reference centroid.

    import pandas as pd
from smint.alignment import build_pretransform, apply_pretransform, describe_pretransform

sm_xy = pd.read_csv("sm_matrix.csv", usecols=["x", "y"]).to_numpy(float)
xenium_xy = pd.read_csv("xenium_cells.csv", usecols=["x_centroid", "y_centroid"]).to_numpy(float)

matrix = build_pretransform(sm_xy, xenium_xy, rotation=90)
sm_pre = apply_pretransform(sm_xy, matrix)
print(describe_pretransform(matrix))   # scale_x, scale_y, rotation_deg, reflects, ...

    smint.alignment.fit_scale_to_reference ¶

    fit_scale_to_reference(source_xy, reference_xy, mode='extent', preserve_aspect=True)

    Scale factors bringing a source dataset onto a reference's coordinate system.

    Parameters:

    Name Type Description Default
    source_xy array - like

    (N, 2) / (M, 2) coordinate arrays.

    		 required
    reference_xy array - like

    (N, 2) / (M, 2) coordinate arrays.

    		 required
    mode (extent, max, none)

    'extent' (default) matches the bounding-box span of each axis, which is robust to the two datasets having different origins. 'max' matches the maximum coordinate directly -- literal, but wrong whenever either dataset does not start near zero. 'none' returns (1.0, 1.0).

    		 'extent'
    preserve_aspect bool

    If True (default), use a single isotropic factor -- the smaller of the two -- so the tissue is not distorted. Anisotropic scaling can force bounding boxes to agree while making the shapes match worse, which then misleads the landmark step.

    		 True

    Returns:

    Name Type Description
    sx float

    Scale factor along x.
    sy float

    Scale factor along y (equal to sx when preserve_aspect).
    Notes

    Bounding boxes are sensitive to outliers: a handful of stray points inflates the span and shrinks the fitted factor. Check the result on a plot, and drop obvious debris before fitting.

    Centroid registration and refinement¶

    For a second modality acquired on the same section, where nuclei and cells correspond one-to-one. register_centroids fits the transform (multiround displacement voting by default) and reports target registration error on held-out points; refine_by_assignment then snaps confidently matched nuclei exactly onto their cells. register_centroid_files does both from two CSV files and is what smint-alignment centroid runs.

    flowchart LR
    A[source centroids] --> B[register_centroids<br/>multiround voting]
    T[target centroids] --> B
    B -->|transform| C[x/y_transformed_smooth]
    C --> D[refine_by_assignment<br/>snap, fill, assign]
    T --> D
    D --> E[x/y_transformed<br/>registration_status]

    smint.alignment.register_centroids ¶

    register_centroids(source_xy, target_xy, method='multiround', max_distance=100.0, mutual=True, validation_fraction=0.25, residual_threshold=10.0, max_trials=1000, tps_regularization=None, n_control=1000, random_state=0, schedule=None, min_improvement=0.01)

    Register two centroid sets acquired from the same physical section.

    multiround (the default) re-matches and refits over several rounds; the single-round methods match once by nearest neighbour, hold out a fraction of the pairs, and fit the rest. All report TRE on held-out data.

    Parameters:

    Name Type Description Default
    source_xy ndarray

    (N, 2) / (M, 2) (x, y) centroids. The source is moved onto the target.

    		 required
    target_xy ndarray

    (N, 2) / (M, 2) (x, y) centroids. The source is moved onto the target.

    		 required
    method (multiround, affine, ransac, tps, ransac + tps)

    Registration model: affine (least squares on all matched pairs), ransac (outlier-robust affine), tps (affine, then a thin-plate spline), ransac+tps (RANSAC affine, then TPS on the inliers) or multiround (coarse-to-fine displacement voting: an affine through per-block displacement peaks, then a smooth TPS through finer blocks; recommended).

    		 'multiround'
    max_distance float

    Correspondence cutoff, in coordinate units.

    		 100.0
    mutual bool

    Require reciprocal nearest neighbours.

    		 True
    validation_fraction float

    Fraction held out from fitting: matched pairs for the single-round methods, source points for multiround. Set to 0.0 only if you accept that the reported TRE is then uninformative.

    		 0.25
    residual_threshold optional

    RANSAC settings (multiround derives each round's threshold from its radius).

    		 10.0
    max_trials optional

    RANSAC settings (multiround derives each round's threshold from its radius).

    		 10.0
    tps_regularization optional

    TPS settings. Regularisation defaults to 1000 for multiround (whose control points are block centres) and 1 for the single-round methods.

    		 None
    n_control optional

    TPS settings. Regularisation defaults to 1000 for multiround (whose control points are block centres) and 1 for the single-round methods.

    		 None
    random_state int

    Seed for the split, RANSAC and control-point sampling.

    		 0
    schedule sequence of (max_distance, block_size, bin_size)

    multiround voting rounds, coarse to fine. Round 1 fits an affine through the block displacements; later rounds add a smooth TPS through them. Default ((max_distance, 500, 2), (0.25 * max_distance, 250, 1)), in coordinate units (microns).

    		 None
    min_improvement float

    multiround keeps a round only if it lowers the fit points' median nearest-target distance by at least this fraction, and stops at the first round that does not.

    		 0.01

    Returns:

    dict

    smint.alignment.refine_by_assignment ¶

    refine_by_assignment(source_xy, target_xy, transform=None, snap_radius=10.0, neighbour_radius=100.0, consistency_tol=None, min_neighbours=5, k_fill=8, validation_fraction=0.1, random_state=0, passes=4, assign_remaining=True, assign_radius=None)

    Snap registered source points exactly onto their partner targets.

    A port of the lab's alignment_refinement.r. A smooth transform leaves each nucleus a few microns from its cell -- partly because a nucleus really is off-centre in its cell. This step instead assigns nuclei to cells and moves each confidently assigned nucleus onto its partner:

    1. Pair transformed source points one-to-one with targets (mutual nearest neighbours within snap_radius).
    2. Keep a pair only if its offset agrees, within consistency_tol, with the median offset of the other pairs within neighbour_radius -- a pairing with the wrong cell disagrees with its neighbourhood.
    3. Snap kept pairs: the source point moves exactly onto its target.
    4. Every other point moves by the median offset of its k_fill nearest snapped neighbours (within neighbour_radius), or not at all.
    5. Repeat: the moved, still-unsnapped points are paired again with the still-unmatched targets, and kept if they agree with the snapped field around them -- up to passes times, until nothing new snaps.
    6. Assign what is left: the filled points and the still-unmatched targets are paired by a minimum-total-distance one-to-one assignment within assign_radius, and each assigned point moves onto its target (status 'assigned'). These pairs skipped the consistency test, so they are less certain than 'snapped' ones; filter on the status if that matters.

    Snapped points coincide with their targets by construction, so their residual says nothing about correctness. The check is validation: a fraction of the kept pairs is left out of the offset field, their positions are predicted from their neighbours alone (step 4), and the distance from each prediction to its partner is reported.

    Parameters:

    Name Type Description Default
    source_xy ndarray

    (N, 2) / (M, 2) points. source_xy in its original frame.

    		 required
    target_xy ndarray

    (N, 2) / (M, 2) points. source_xy in its original frame.

    		 required
    transform callable

    Registration to apply first (e.g. register_centroids(...)["transform"]). Default: none, source_xy is already registered.

    		 None
    snap_radius float

    Maximum distance for a pair.

    		 10.0
    neighbour_radius float

    Neighbourhood for the consistency test and for filling in.

    		 100.0
    consistency_tol float

    Allowed deviation from the neighbourhood's median offset. Default 0.4 x the target's median nearest-neighbour spacing.

    		 None
    min_neighbours int

    Pairs with fewer neighbouring pairs than this cannot be checked and are not snapped.

    		 5
    passes int

    Pairing passes (step 5); 1 disables re-pairing.

    		 4
    assign_remaining bool

    Run step 6.

    		 True
    assign_radius float

    Maximum distance for step 6. Default 0.75 x the target's median nearest-neighbour spacing.

    		 None
    k_fill int

    Snapped neighbours whose median offset moves an unsnapped point.

    		 8
    validation_fraction float

    Fraction of kept pairs used for the held-out check.

    		 0.1

    Returns:

    Type Description
    dict

    refined_xy ((N, 2)), status ('snapped', 'assigned', 'filled' or 'unmoved' per point), target_idx (partner index, -1 if none), neighbour_deviation (per placed point: distance between its offset and its snapped neighbourhood's median offset -- small for right pairs, about a cell spacing for wrong ones), n_snapped, fraction_snapped (of source points), fraction_targets_matched, consistency_tol and validation (median_error, within_2, within_5 for the held-out pairs).

    smint.alignment.vote_block_displacements ¶

    vote_block_displacements(source_xy, target_xy, max_distance, block_size, bin_size=2.0, k=None, min_points=25)

    Estimate the local source -> target displacement in square blocks.

    Every source point votes for the displacements to its k nearest targets within max_distance. Wrong candidates point in random directions, but the true offset is shared by every point in the block, so it is the peak of the (lightly smoothed) 2D vote histogram. This works even when the misalignment exceeds the cell spacing, where nearest-neighbour matching cannot -- provided the tissue is not a regular lattice, whose periodicity makes every whole-spacing shift look equally good.

    k defaults to the expected number of targets within max_distance (from the target density, capped at 128), so the true partner is among the candidates anywhere in that radius.

    Returns:

    Name Type Description
    centres ndarray

    (B, 2) centroids of the blocks holding at least min_points source points.
    displacements ndarray

    (B, 2) modal source -> target displacement of each block.

    ST–SM registration (sequential sections)¶

    For spatial metabolomics (SM) and spatial transcriptomics (ST) from different sections. STalign's LDDMM does the warping, initialised from landmarks you pick by hand, so the workflow has two phases around a manual step:

    flowchart LR
    A[ST CSV + SM matrix] --> B[prepare_landmark_inputs<br/>rasterise, write .npz]
    B --> C[pick landmarks<br/>napari plugin or point annotator]
    C --> D[_st_points.npy<br/>_sm_points.npy]
    D --> E[register_sm_to_st<br/>landmark-initialised LDDMM]
    A --> E
    E --> F[sm_transformed.csv<br/>x/y_transformed]

    These functions import STalign, which needs numpy < 2 and torch. Run them in a worker environment (stalign_available tells you whether the current one qualifies), or submit them with the Jobs API.

    smint.alignment.read_sm_matrix ¶

    read_sm_matrix(mtx_file, scale_xy=10.0, rotate_left_90=False, keep_positive=True, origin=None, usecols=None, x_col=None, y_col=None, verbose=True)

    Read a spatial metabolomics matrix file and normalise it for registration.

    Applies, in order: delimiter sniffing, x/y name standardisation, X-prefixing of numeric m/z headers, coordinate scaling, optional 90 deg CCW rotation, and an optional shift to keep coordinates non-negative.

    The SM grid is stored in pixel units; scale_xy converts it to the same micron scale as the ST centroids, so registration starts near the right magnitude. For the MALDI data SMINT was developed on this is 10.0.
